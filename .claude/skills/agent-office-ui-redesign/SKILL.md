# Agent Office: UI redesign rules

Simplify before restyling. Show less at once, give each view a clear hierarchy, and leave one obvious next action per view.

- Keep every existing function; change how it is reached and shown, not what it does.
- No emoji anywhere in the UI (buttons, status, tabs, errors, close buttons). Use one consistent set of thin line icons: single-colour strokes with `currentColor`, rounded caps and joins, Apple SF Symbols style, held in one icon map in the front-end code. Playback and close icons stay full Apple-style controls. Replace every emoji in the view at once, and check the icons in light and dark mode.
- Redesign the whole surface together: hallway/repo list, project workspace, office scene, agent panels, dialogs, outputs. Do not leave old-style screens next to new ones.
- The office visual must match the new concept; do not keep the previous scene style.
- Check selected and active states in both themes. A selected segment or chip must keep every piece of text readable: a sub-line such as the time estimate that inherits the selected background colour can vanish (green on green). Give secondary text an explicit colour that contrasts with the selected background.
- Window behaviour: no window or side panel closes by itself. Every dialog and side panel closes when the user clicks outside it; clicks inside it, or drag-selecting text, do not close it. A pending agent question stays pending when its window is closed; its button reopens the window and shows a count. Replace a "⋯" overflow menu with direct controls (for example a pencil beside the project name) instead of hiding actions behind it.
- Before adding a hover or active override, grep `public/` for existing `:hover` rules on the same class, especially `!important` ones, and remove or scope them. A card title that vanished on hover came from an older rule.
- Dialogs and panels carry a title, the controls and the content. No intro paragraph, legend or instruction line under the controls, and no numbering in section headings ("1 · …"). The user removed the intro sentence, the "Vždy = bez ptaní · Zeptat se = … · Nikdy = …" legend and the "Po kliknutí na Povolit…" note from Mac access and asked for a polished look instead. If a numbering scheme or hint text is removed, update `README.md` and `README.cs.md` in the same change (the README still said "Část 1/2/3" afterwards). Give a dialog a fixed width such as `min(680px, 100vw - 32px)`; at 520 px every description wrapped.
- Verify light and dark mode, dialogs, and phone width (no horizontal overflow) before finishing.
- Form fields, selects, segmented switches, buttons and progress bars must match the app's own look, not a browser default: the same font family, the rounded or pill radius, the card and line colours from `pro.css` variables (`--acc`, `--line2`, `--card`, `--bg2`), and the green accent border on focus. Limit and progress bars use the project-progress green and turn amber under 20 %. Check these with `getComputedStyle` (colour, font-family, border-radius) in both themes, and compare with an existing field before calling the screen done. The user asked for this in two separate messages: once about the progress colours and fonts, once about the fields not matching "našeho UI".
- Rebuild and reinstall via agent-office-reinstall, then send screenshots of the installed app.
- When another session owns the backend in the same folder, stay in UI files only.
- Team members live in the office panel, not in a separate left column. The panel header has a segmented switch "Kancelář | Přehled N" (N = member count; no status text or live dot next to it) with a green "+ Přidat roli" button of the same height on the right that flips between the office scene and the team view, and the choice is remembered. The team view is a wrapping grid of member blocks (portrait, name, role, status, model) in several rows, not a plain list. When there are many members it scrolls inside the panel, at the same height as the scene, so the page itself does not grow. The "+N" control on the scene opens the team view.
- After a Bash `sed` or python edit to a file you already read, Read that file again before the next Edit; the edit tool rejects stale reads.
- Auto-growing textareas (the boss chat, the agent chat): when a send clears the value, also reset `style.height` to `''`. Otherwise the box keeps its grown height after sending. Check it by filling three lines, sending, and reading the height back.
- Every user-visible string goes into `public/i18n.js` in both English and Czech. English is the default. The language is chosen only on the first-launch setup screen (EN | CS buttons stored in `config.json`), not in the main header, so do not add a language switch to the header; later changes go through View → Set Up Tools. Do not hardcode Czech text in a view. The boss's replies follow the same language setting.
- When a behavior or screen changes, update `README.md` and `README.cs.md` in the same change so both still describe the same thing.
- Renaming a visible label (for example "Nový cíl" to "Nové zadání") touches the view, both language keys in `public/i18n.js`, and both README files in one change. Grep the old string afterwards to confirm nothing is left.
- Card hover changes size only (about 2.5% scale) plus a stronger frame and shadow. Never change the title or text colour on hover; the user rejected that version.
- Secondary controls stay closed by default: a token paste box, a second sign-in path or advanced options sit behind one pill-shaped disclosure button (for example a `<details>` labelled "Připojit znovu") and open only on click. The user asked for exactly this on the Claude reconnect block. Keep the disclosure open across the automatic provider-list refresh, and re-check that after the re-render.
- Project run controls (Pozastavit, Zastavit, Pokračovat) sit at the end of the progress row, in the same pill shape as the steps, not in the header. Colour carries the action: green continue, amber pause (the same amber a paused or waiting step uses), red stop and error. Do not keep a separate "Pozastaveno" status label next to the project title; show the state as the icon on the current step (pause icon when paused, stopped or at a limit, question mark when waiting for the user, warning triangle for error or budget). On phone width the controls wrap under the steps; check that with `scrollWidth` against `innerWidth`.
- Verify UI on a throwaway server: choose a free port, set `AGENT_OFFICE_HOME` to a scratch folder and `AGENT_OFFICE_TOKEN=dev`, then open `/?t=dev&demo=1&view=office&n=6`. Click CS and check `AO_I18N.lang` and `document.documentElement.lang`. Afterwards stop that server by its port, delete the scratch home, and reset the browser viewport with preset `desktop`.
- Test close-on-outside-click with a real click on empty scene space and on another agent, not by reading the code. A panel that never closed on outside click was found only this way. Report which states were tested in the browser and state that the installed Mac app was not checked when it was not.
